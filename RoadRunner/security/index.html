Trust posture

Security claims should be specific enough to review.

This page now covers the minimum categories a security reviewer will expect before deeper due diligence.

Data handling

Evidence is collected for assessment, reporting, validation, and source-health visibility.

Encryption

Use encrypted transport for uploads and encrypted storage for retained evidence and reports.

Access control

Limit access by tenant, role, and operational need. Revoke customer access paths during offboarding.

Tenant isolation

Keep customer evidence scoped by tenant and separate client surfaces for MSP delivery.

Logging

Track connector status, evidence freshness, access activity, and validation runs.

Retention

Set retention during the pilot or contract; delete or export evidence during offboarding as agreed.

Data handling

Make offboarding and limits explicit.

This is the difference between a trust page and vague reassurance.

Retention

Pilot retention should be defined before access is granted. Long-term retention follows the contract and reporting needs.

Offboarding

Revoke connectors, export agreed reports, delete retained evidence according to the agreed timeline, and confirm completion.

Subprocessors

List hosting, email, analytics, and operational subprocessors before production procurement. If none are used for a category, say so.

Boundaries

What RoadRunner does not do by default.

Explicit boundaries reduce fear and prevent the product from sounding like an exploit platform.

No destructive testing

The assessment observes configuration and evidence. Destructive testing is not part of default behavior.

No credential collection

Collectors do not harvest passwords, hashes, tokens, or secrets.

No automatic changes

RoadRunner recommends fixes. Customers or MSPs execute approved changes.

Disclosure path

Send security reports to drew@roadrunnerstrategies.com. Acknowledge valid reports and coordinate remediation directly.
